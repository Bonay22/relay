## Результат этапа

Relay умеет создать корректное событие с типом, начальным статусом,
произвольным payload и временем создания. Метод события меняет его статус, а
`main` наглядно показывает успешный и ошибочный сценарии.

Поток данных этапа:

```text
EventType + payload
        ↓
     NewEvent
        ↓
Event{Type, Status, Payload, CreatedAt}
        ↓
 MarkDelivered / вывод результата
```

## Учебный scope

### Core

Эти концепции нужны для результата этапа и должны быть применены в коде:

- определённые строковые типы и typed-константы;
- структура, поля, composite literal и selector;
- функция с результатом `(value, error)`, `nil` и ранний возврат;
- создание простой ошибки;
- value и pointer semantics на примере изменения статуса;
- `map[string]any` для произвольного payload;
- `time.Time` и получение текущего времени через пакет `time`.

### Later

Изучаем при первом реальном использовании: JSON struct tags, подробное
кодирование JSON, глубокое копирование map, строки и UTF-8, циклы, `switch`,
variadic-функции, wrapping ошибок и подробная работа с часовыми поясами.

### Reference

Достаточно знать, где найти: все формы числовых и других литералов, комплексные
числа, автоматическая вставка `;`, `goto` и прочие детали спецификации, которые
не нужны модели события.

Только Core может удерживать этап открытым. Глобальная
[`GO-KNOWLEDGE-MAP.md`](GO-KNOWLEDGE-MAP.md) используется как справочник, а не

## Завершённый инкремент: payload события

`Event` получил поле `Payload map[string]any`, а `NewEvent` принимает и
сохраняет переданную map. `main` создаёт событие с `order_id` и читает это
значение по ключу.

Зафиксированная модель:

- ключи имеют тип `string`, а результат чтения — статический тип `any`;
- nil map доступна для чтения, но запись в неё вызывает panic;
- литерал `map[string]any{}` создаёт пустую map, готовую к записи;
- конструктор пока не копирует payload, поэтому исходная map и поле события
  наблюдают общее внутреннее состояние.

Это представление данных в памяти, а не декодирование JSON. Вопрос защитного
копирования вернётся на границе отдельного доменного пакета и конкурентной
доставки.

## Завершённый инкремент: время создания события

`Event` получил поле `CreatedAt time.Time`. На успешном пути `NewEvent`
назначает ему результат `time.Now()`, поэтому каждый корректно созданный объект
содержит ненулевой момент создания. Ошибочный путь возвращает `Event{}`, где
`CreatedAt` равен `0001-01-01 00:00:00 +0000 UTC`.

Подтверждено, что `time.Now()` возвращает значение `time.Time`, но ничего не
выводит самостоятельно, а `IsZero()` возвращает `bool` и отличает zero time от
назначенного момента.

## Завершённый инкремент: итоговая демонстрация

`main` связывает готовые доменные операции, не дублируя их правила: создаёт
событие, проверяет ошибку, показывает начальный статус, вызывает
`MarkDelivered`, а затем отдельно демонстрирует ошибочный путь конструктора.

Итоговый поток:

```text
NewEvent(OrderCreated, payload)
              ↓
      вывод pending-события
              ↓
        MarkDelivered()
              ↓
      вывод delivered-статуса
              ↓
       NewEvent("", nil)
              ↓
         вывод ошибки
```

Наблюдаемый результат показывает `pending`, затем `delivered`, payload успешного
события, ненулевой `CreatedAt`, текст ошибки пустого типа и нулевой `CreatedAt`
возвращённого `Event{}`.

## Решения и ход реализации

### Что уже принято

- Созданы `EventType`, `OrderCreated` и `OrderPaid`.
- Созданы `EventStatus`, `EventPending` и `EventDelivered`.
- `Event` хранит тип и статус.
- `NewEvent` возвращает `(Event, error)`, отклоняет пустой тип и назначает
  начальному событию статус `EventPending`.
- `MarkDelivered` использует pointer receiver, безопасно отклоняет nil receiver
  и изменяет статус существующего события.
- `Event` хранит произвольный payload, а `NewEvent` сохраняет переданную map без
  защитной копии.
- `Event` хранит `CreatedAt`, который конструктор назначает через `time.Now()`
  только после успешной валидации типа.
- `main` оркестрирует успешное создание, смену статуса и ошибочный сценарий,
  проверяя ошибки до продолжения соответствующего пути.

Ученик реализовал эти изменения самостоятельно и объяснил defined types,
typed/untyped constants, структуру, копирование значения, `(value, error)`,
ранний возврат, значение/указатель, мутацию через pointer receiver, zero time и
роль конструктора в поддержании корректного состояния.

### Осознанно отложено

- Проверка допустимости перехода статуса будет добавлена тогда, когда появится
  реальная модель состояний.
- Систематические автоматические тесты начинаются на этапе 02.
- Публичный API отдельного доменного пакета проектируется на этапе 04.
- Подробные темы, пройденные до checkpoint, остаются доступными в истории, но
