## Результат этапа

Relay умеет создать корректное событие с типом, начальным статусом,
произвольным payload и временем создания. Метод события меняет его статус, а
`main` наглядно показывает успешный и ошибочный сценарии.

Поток данных этапа:

```text
EventType + payload
        ↓
     NewEvent
        ↓
Event{Type, Status, Payload, CreatedAt}
        ↓
 MarkDelivered / вывод результата
```

## Учебный scope

### Core

Эти концепции нужны для результата этапа и должны быть применены в коде:

- определённые строковые типы и typed-константы;
- структура, поля, composite literal и selector;
- функция с результатом `(value, error)`, `nil` и ранний возврат;
- создание простой ошибки;
- value и pointer semantics на примере изменения статуса;
- `map[string]any` для произвольного payload;
- `time.Time` и получение текущего времени через пакет `time`.

### Later

Изучаем при первом реальном использовании: JSON struct tags, подробное
кодирование JSON, глубокое копирование map, строки и UTF-8, циклы, `switch`,
variadic-функции, wrapping ошибок и подробная работа с часовыми поясами.

### Reference

Достаточно знать, где найти: все формы числовых и других литералов, комплексные

## Текущий инкремент: payload события

### Что добавляем и зачем

Разные события несут разные данные. У `order.created` это могут быть
`order_id`, сумма и адрес, а у `order.paid` — идентификатор платежа. На этом
этапе представляем такие данные типом `map[string]any`:

- `string` задаёт единый тип ключей;
- `any` позволяет значениям иметь разные конкретные типы;
- map позволяет обратиться к значению по ключу без отдельного поля структуры
  для каждого варианта события.

Это ещё не JSON. `map[string]any` — только представление данных в памяти;
преобразование байтов JSON появится на HTTP-этапе.

### Минимальная модель map

```go
payload := map[string]any{
    "order_id": 42,
    "paid":     false,
}

orderID := payload["order_id"]
payload["paid"] = true
```

Здесь оба ключа имеют тип `string`. Переменные значения хранятся через `any`,
поэтому `orderID` имеет статический тип `any`, даже если внутри сейчас лежит
`int`. Чтобы выполнять операции именно как с `int`, позже понадобится проверка
конкретного типа.

У map есть важные свойства:

- zero value map равен `nil`; из него можно читать, но запись вызовет panic;
- `map[string]any{}` создаёт пустой, но готовый к записи map;
- присваивание или передача map не копирует все пары: несколько переменных
  могут наблюдать изменения одних и тех же данных.

В текущем инкременте `NewEvent` сохраняет переданную map без защитной копии.
Это сознательное простое решение; вопрос владения и копирования вернётся при
появлении конкурентной доставки.

### Задание

Самостоятельно выполни один ограниченный шаг:

1. Добавь в `Event` экспортируемое поле `Payload` типа `map[string]any`.
2. Измени сигнатуру `NewEvent`, чтобы она принимала payload вторым аргументом.
3. Сохрани переданный payload в создаваемом событии.
4. Обнови вызов в `main`, чтобы проект снова собирался. Передай небольшой map
   literal; текущий ошибочный сценарий с пустым типом можно пока сохранить.

Не добавляй валидацию payload, копирование map, JSON, тесты и время создания —
это вне границы текущего задания.

### Критерий готовности

- `Event` хранит `Payload`;
- `NewEvent` принимает и сохраняет переданную map;
- пустой `eventType` по-прежнему возвращает ошибку;
- `go run ./cmd/relay`, `go vet ./...` и `go test ./...` завершаются ожидаемо;
- ученик может объяснить `string`, `any`, nil/empty map и отсутствие глубокой
  копии в текущем конструкторе.

После реализации проводится одно ревью и задаются 2–3 общих вопроса по всему
инкременту.

## Решения и ход реализации

### Что уже принято

- Созданы `EventType`, `OrderCreated` и `OrderPaid`.
- Созданы `EventStatus`, `EventPending` и `EventDelivered`.
- `Event` хранит тип и статус.
- `NewEvent` возвращает `(Event, error)`, отклоняет пустой тип и назначает
  начальному событию статус `EventPending`.
- `MarkDelivered` использует pointer receiver, безопасно отклоняет nil receiver
  и изменяет статус существующего события.
- `main` вызывает `NewEvent` и проверяет ошибку до использования результата.

Ученик реализовал эти изменения самостоятельно и объяснил defined types,
typed/untyped constants, структуру, копирование значения, `(value, error)`,
ранний возврат, значение/указатель и мутацию через pointer receiver.

### Осознанно отложено

- Проверка допустимости перехода статуса будет добавлена тогда, когда появится
  реальная модель состояний.
- Систематические автоматические тесты начинаются на этапе 02.
- Публичный API отдельного доменного пакета проектируется на этапе 04.
- Подробные темы, пройденные до checkpoint, остаются доступными в истории, но
  не являются условиями завершения этого этапа.
