# Relay

Relay — учебный Go-проект и будущий сервис надёжной доставки событий по
webhook. Проект развивается небольшими рабочими этапами: каждый этап добавляет
наблюдаемую возможность и закрепляет связанные с ней темы Go.

## Текущее состояние

Начат этап 04 — доменная модель вынесена во внутренний пакет, а события можно
сохранять, получать и просматривать через application service и memory
repository. HTTP-интеграция этого хранилища будет добавлена следующим
инкрементом.

Сейчас Relay умеет:

- описывать событие через тип, статус, payload и время создания;
- создавать событие с начальным статусом `pending`;
- отклонять событие без типа;
- переводить событие в статус `delivered`;
- возвращать распознаваемые sentinel-ошибки;
- отвечать на `GET /health`;
- принимать `POST /v1/events` и возвращать созданное событие с кодом `201`;
- отклонять malformed JSON, неизвестные поля и второе JSON-значение;
- возвращать ошибки HTTP API в едином JSON-формате;
- проверять доменную модель и HTTP-контракт автоматическими тестами без
  открытия сетевого порта.
- назначать сохранённому событию стабильный `EventID`;
- сохранять события в памяти, получать их по ID и выдавать в порядке сохранения;
- изолировать верхний уровень `Payload` от изменений вызывающего кода;
- защищать memory repository через `sync.RWMutex`.

`POST /v1/events` пока сохраняет прежнее поведение: он создаёт событие и
возвращает его клиенту, но ещё не передаёт его в memory repository. Данные
memory repository живут только до остановки процесса. Подписки и реальная
доставка webhook будут добавлены на следующих этапах.

## Требования

- Go 1.26.4 согласно `go.mod`.

## Запуск

Из корня репозитория:

```bash
go run ./cmd/relay
```

Ожидаемый вывод:

```text
service=Relay version=0.2.0
YYYY/MM/DD HH:MM:SS server listening on 127.0.0.1:8080
```

После запуска сервер занимает текущий терминал и принимает запросы на
`127.0.0.1:8080`. Для остановки нажмите `Ctrl+C`.

## HTTP API

Проверка состояния сервиса:

```bash
curl -i http://127.0.0.1:8080/health
```

Ответ содержит статус `200 OK` и JSON:

```json
{"status":"ok"}
```

Создание события:

```bash
curl -i \
  -X POST http://127.0.0.1:8080/v1/events \
  -H 'Content-Type: application/json' \
  -d '{"type":"order.created","payload":{"order_id":"A-10"}}'
```

Ответ содержит статус `201 Created`. Значение `created_at` будет соответствовать
фактическому времени создания события:

```json
{"type":"order.created","status":"pending","payload":{"order_id":"A-10"},"created_at":"2026-08-30T12:00:00Z"}
```

Некорректное тело запроса получает статус `400 Bad Request` и стабильный JSON с
описанием ошибки, например:

```json
{"error":"invalid request body"}
```

## Проверки

```bash
gofmt -d cmd/relay/*.go
go vet ./...
go test ./...
```

Пустой вывод `gofmt` и `go vet` означает, что они не нашли изменений или
диагностик. Успешный `go test` выводит результат проверки пакета.

## Сборка

```bash
go build -o relay ./cmd/relay
./relay
```

Первая команда создаёт локальный бинарный файл `relay`, но не запускает его.
Вторая команда запускает HTTP-сервер. Бинарный файл исключён из Git.
